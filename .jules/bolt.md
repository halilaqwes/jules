## 2024-05-20 - Lifting state up in React can cause severe layout thrashing
**Learning:** In the frontend React application, lifting state up to a central layout component (like tracking `CodeEditor` keystrokes in `MainLayout` using `setCode`) causes all child components to re-render. If heavy sibling components like `AgentSidebar`, `ChatPanel`, and `FileExplorer` are not memoized, this causes severe layout thrashing and unnecessary reconciliation on every keystroke. Even simple inline callbacks (like `onFileSelect`) will break `React.memo` if they are not wrapped in `useCallback`.
**Action:** When a parent component manages frequently updating state (like text editor input), always ensure that heavy sibling components are wrapped in `React.memo` and that their callback props are stabilized using `useCallback` to prevent cascading re-renders.
