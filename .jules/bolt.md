## 2024-05-14 - React Sibling Component Thrashing & Memory Leak
**Learning:** In the React frontend, lifting state up to a central layout component (like `MainLayout` holding `code` for `CodeEditor`) causes severe layout thrashing. Because `code` updates on every single keystroke, all sibling components (`AgentSidebar`, `FileExplorer`, `ChatPanel`) were unnecessarily re-rendering in real-time, creating significant input lag in the `CodeEditor`.
**Action:** Always heavily leverage `useMemo` for sibling components and `useCallback` for event handlers when lifting state up to a central layout component in a complex UI with a fast-firing state change (like a code editor's input). Alternatively, keep state closer to the components that need them (e.g. state management solutions or passing only IDs instead of complete values).
