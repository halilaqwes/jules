## 2024-10-25 - [Frontend Performance: Prevent layout thrashing with React.memo on heavy siblings]
**Learning:** In the frontend React application, lifting state up to a central layout component (like tracking `CodeEditor` keystrokes in `MainLayout`) requires heavy sibling components (`AgentSidebar`, `FileExplorer`, `ChatPanel`) to be memoized using `React.memo` or `useMemo`, and callbacks using `useCallback` to prevent severe layout thrashing and unnecessary reconciliation on every keystroke. Also, to resolve ESLint `react-hooks/set-state-in-effect` errors when fetching data on mount, wrap the initial fetch call inside the `useEffect` with `setTimeout` to push the state update to the macro-task queue and avoid synchronous setState warnings.
**Action:** Always verify if state changes in a parent component propagate to expensive but unrelated sibling components, and defensively memoize them with React.memo when appropriate. Wrap on-mount data fetching that updates state within a setTimeout inside useEffect if synchronous setState warnings occur.
